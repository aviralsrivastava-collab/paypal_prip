## 3. Webhook ID Verification & PayPal Schema Constraint

PayPal's signature verification service enforces strict syntactic schema validation on the `webhook_id` field.

A probe was dispatched to `POST https://api-m.sandbox.paypal.com/v1/notifications/verify-webhook-signature` using the active OAuth bearer token:

### Sanitized PayPal API Error Evidence
```http
POST /v1/notifications/verify-webhook-signature HTTP/1.1
Host: api-m.sandbox.paypal.com
Authorization: Bearer [REDACTED]
Content-Type: application/json

HTTP/1.1 400 Bad Request
Content-Type: application/json

{
  "name": "INVALID_REQUEST",
  "message": "Request is not well-formed, syntactically incorrect, or violates schema.",
  "debug_id": "f290998538c2e",
  "details": [
    {
      "field": "/webhook_id",
      "value": "WH-MOCK-SANDBOX-001",
      "location": "body",
      "issue": "must match \"^[a-zA-Z0-9]+$\""
    }
  ],
  "links": []
}
```

**Technical Implication:**
- The placeholder `WH-MOCK-SANDBOX-001` contains hyphens and is immediately rejected by PayPal's gateway before cryptographic signature math is evaluated.
- To achieve successful signature verification, a real alphanumeric Webhook ID (e.g. `8JH90214XX839210L`) generated by PayPal upon registering the public URL must be placed in `.env`.

## 5. Webhook Simulator Limitations vs. Actual Live Delivery

When using PayPal's **Webhook Simulator** (in PayPal Developer Dashboard under Testing Tools):

1. **Synthetic Header Generation:**
   - The simulator transmits synthetic headers (`paypal-transmission-id`, `paypal-cert-url`, etc.) signed by PayPal's sandbox simulation key.
   - These are cryptographically verifiable by PayPal's `/v1/notifications/verify-webhook-signature` endpoint only if the Webhook ID selected in the simulator matches the `webhook_id` passed in the verification request.
2. **Order Disconnection:**
   - Simulated events (e.g. simulated `PAYMENT.CAPTURE.COMPLETED`) contain dummy resource IDs (e.g. `CAPTURE-SIMULATED-12345`) rather than references to orders existing in PRIP's local database.
   - **PRIP Behavior on Unassociated Events:** PRIP correctly ingests the simulated event into `webhook_events`, marks status `PROCESSED`, attributes the audit log to `platform_system`, and logs `WEBHOOK_PROCESSED` without mutating unrelated demo orders.
3. **Distinction from Real Delivery:**
   - A simulator test verifies **network reachability, raw body preservation, cryptographic signature verification, inbox persistence, and worker claiming**.
   - An actual checkout delivery (Phase 10B) additionally verifies **order status transition (`CREATED` &rarr; `APPROVED` &rarr; `COMPLETED`) and inventory reservation commit (`ReservationStatus.COMMITTED`)**.

## 6. Actionable Steps to Complete Live Delivery Validation

To transition from `PARTIAL — SIGNATURE OR DELIVERY VALIDATION PENDING` to `SANDBOX WEBHOOK VERIFIED`:

### Step 1: Start Local Backend Listener
Start the PRIP FastAPI backend on port 8000:
```powershell
.venv\Scripts\uvicorn.exe backend.api.main:app --host 127.0.0.1 --port 8000
```

### Step 2: Launch Path-Restricted Public HTTPS Tunnel
Start ngrok with traffic-policy restriction (or Cloudflare Tunnel):
```powershell
ngrok http 8000 --request-header-add "X-Forwarded-Proto: https"
```
*Note the public HTTPS URL (e.g. `https://xxxx-xx-xx.ngrok-free.app`).*

### Step 3: Register Webhook in PayPal Developer Dashboard
1. Go to [https://developer.paypal.com/dashboard/applications/sandbox](https://developer.paypal.com/dashboard/applications/sandbox).
2. Select your REST API application.
3. Under **Sandbox Webhooks**, click **Add Webhook**.
4. URL: `https://xxxx-xx-xx.ngrok-free.app/api/webhooks/paypal`.
5. Select events:
   - `Checkout order approved`
   - `Payment capture completed`
   - `Payment capture denied`
   - `Payment capture declined`
6. Click **Save** and copy the generated alphanumeric Webhook ID.

### Step 4: Configure `PAYPAL_WEBHOOK_ID` in `.env`
Update `.env`:
```bash
PAYPAL_WEBHOOK_ID=<PASTE_ALPHANUMERIC_WEBHOOK_ID>
```
Restart Uvicorn so the new configuration loads.

### Step 5: Execute Webhook Simulator Delivery
1. In PayPal Developer Dashboard &rarr; **Testing Tools** &rarr; **Webhook Simulator**.
2. Select your registered Webhook ID and event `Payment capture completed`.
3. Click **Send Test**.
4. Confirm HTTP 200 response in Uvicorn log and inspect database record in `webhook_events`.
